# 커밋 작성 절차

1. `git status`와 `git diff`로 변경 내용을 먼저 확인한다.
2. 변경을 논리적 단위로 나눌 수 있으면 나눠서 커밋한다.
3. 커밋 메시지는 아래의 커밋 컨벤션을 따른다.
4. 본문에는 "무엇을"이 아니라 "왜" 바꿨는지를 적는다.
5. 현재 작업한 파일 이외의 관련 없는 파일은 커밋하지 않는다.

# 커밋 컨벤션

## 커밋 제목 형식
`type: 한국어 설명`

## type 선택 (하나)
- `feat`: 새로운 기능 (API 엔드포인트, 페이지, 모달 등)
- `fix`: 버그 수정 (쿼리 오류, 로직 수정 등)
- `refactor`: 코드 리팩토링 (중복 제거, 메서드 추출, 패키지 구조 정리)
- `test`: 테스트 추가/수정 (JUnit, Mockito, WireMock)
- `docs`: 문서 추가/수정 (README, CLAUDE.md)
- `chore`: 빌드/의존성/설정 (build.gradle, application.yml, Docker)
- `ci`: CI/CD 파이프라인 (GitHub Actions)
- `perf`: 성능 최적화 (쿼리 최적화, 캐싱, 인덱싱)

## 커밋 제목 규칙
- **한국어**로 작성
- 50자 이내로 간결하게 작성
- 마침표를 붙이지 않는다.
- 명령문으로 작성한다. ("추가함", "추가했음"이 아니라 "추가")

## 제목 형식 예시
```
feat(content): 비밀번호 재설정 기능 구현
fix(advertisement): 파싱가능검사 로직에 User-Agent 설정 추가
refactor: 중복 변환 로직을 헬퍼 메서드로 추출
test: PasswordResetService 단위 테스트 작성
chore: build.gradle에 Redis 의존성 추가
```

## 커밋 본문 규칙
- 본문에는 어떻게 아닌 무엇을, 왜 했는지를 명시
- 적절한 작업 단위에 맞게 commit 수행(특히 기능과 테스트는 분리해서 커밋)
- 필요한 경우 이 변경이 왜 필요했는지, 기존방식에서 왜 변경했는지 명시
- "-"로 구분
- 클로드 코드 명시는 제거("Co-Authored-By: ~~" 의 마지막 문장은 제거)
- 클로드 코드 관련 내용은 커밋 메시지에서 제거

## 본문 형식 예시
```
- 기존에는 신용카드 결제만 지원했으나 모바일 사용자 비중이 높아져 간편결제 수요가 증가
- 신규 결제 수단 확장 시 인터페이스 구현만으로 대응할 수 있도록 설계.
```
